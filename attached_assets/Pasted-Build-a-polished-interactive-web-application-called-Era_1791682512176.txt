# 1. THE PROBLEM

Companies receive requests from people who want their personal data deleted under GDPR.

However, personal information is scattered across different systems, such as Slack and Salesforce. Compliance teams must manually find the information, determine what can be deleted, execute the necessary actions, and verify the results.

EraseFlow demonstrates how this workflow could be automated.

Our product workflow is:

**REQUEST → DISCOVER → CLASSIFY → REVIEW → EXECUTE → VERIFY → CERTIFICATE**

# 8. CLASSIFICATION

Each discovered record should receive one of four proposed actions.

### DELETE
The record primarily belongs to the requester.

### REDACT
The record contains the requester's personal information but also contains information about other people that should be preserved where appropriate.

### RETAIN REVIEW
The record may be subject to a legal or regulatory retention requirement. A human must determine whether retention is justified.

### MANUAL REVIEW
The match or record ownership is ambiguous.

For every recommendation, display:
- Recommended action
- Short explanation
- Match evidence
- Confidence indicator

Use deterministic rules for this POC. No external AI is required.

Do not claim that the application independently determines legal retention obligations.

# 9. HUMAN REVIEW QUEUE

Create a dedicated Review Queue page.

Show each discovered record as a row or card.

For each record, allow the reviewer to:
- Approve the recommended action
- Change the proposed action
- Reject the recommendation
- Add a short justification

Use action options:
- DELETE
- REDACT
- RETAIN
- MANUAL REVIEW
- REJECT

Display a clear approval status.

Provide a primary button:

**Execute Approved Actions**

Do not modify records before the user approves the proposed action.

Records classified as RETAIN REVIEW must have a documented justification before being treated as resolved.

MANUAL REVIEW records cannot be silently marked complete.

# 10. EXECUTION

When the user clicks "Execute Approved Actions," execute the approved actions against the synthetic datasets.

### DELETE
Remove the record from the active dataset.

### REDACT
Replace the requester's identifying information with "[REDACTED]" while preserving unrelated content.

### RETAIN
Leave the record intact and store the reviewer's documented retention justification.

### MANUAL REVIEW
Leave the record unchanged and mark it unresolved.

### REJECT
Do not execute the proposed action. Require a documented reason and keep the disposition visible for further handling.

Display a summary of successful actions and any failures.

Use a confirmation dialog before executing actions.

All modifications should be reversible through a Reset Demo button.

# 11. VERIFICATION

After execution, show a dedicated verification page.

Include a button:

**Verify Results**

When clicked, rerun discovery against the modified active datasets.

Display:
- Successfully deleted records
- Successfully redacted records
- Records retained with justification
- Records still requiring review
- Failed actions
- New or reappearing matches

Show one of two prominent statuses.

### COMPLETE
Every discovered record has a documented disposition, all required actions succeeded, and verification found no unresolved actionable matches.

### INCOMPLETE
Some records remain unresolved, an action failed, or a previously deleted record reappeared.

Zero search hits alone must not automatically establish legal compliance.
